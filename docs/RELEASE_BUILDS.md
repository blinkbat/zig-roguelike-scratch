# Release builds

Run from the repository root with Python 3.9+ and Zig 0.14.1. Windows wrappers
use the existing `_zig.cmd` toolchain definition and never launch the game.

## Linux

```powershell
./build-linux.cmd
```

On a host with Zig on PATH, the equivalent command is:

```sh
python3 tools/release.py linux
```

The output is `zig-out/releases/cistern-linux-x86_64.tar.gz`, with a SHA-256
sidecar. Extract it into a writable directory on Linux and run `./run.sh`.
The launcher selects its own directory so maps and saves are found. The archive
preserves every current `.map` under `maps/`, including subfolders, and includes
embedded artwork/fonts, relevant license notices and `build-info.json`; it never
includes saved runs.

The target is baseline x86-64 with glibc 2.31, X11/XWayland and OpenGL 3.3.
The README inside the archive lists runtime packages. System graphics libraries
are supplied by Linux, rather than bundled from the build environment.

## macOS

```powershell
./build-macos.cmd
```

This builds both `cistern-macos-arm64.tar.gz` for Apple Silicon and
`cistern-macos-x86_64.tar.gz` for Intel under `zig-out/releases/`. Both target
macOS 11 or newer. Use `--arch arm64` or `--arch x86_64` to build just one.
With Zig on PATH, use `python3 tools/release.py macos`.

Extract the matching archive into a writable directory and run `./run.sh` in
Terminal, or double-click `run.command`. These are portable development folders,
not `.app` bundles. Saves stay beside the executable, as on Windows and Linux.
The Apple Silicon executable has its ad-hoc code signature generated by Zig;
the helper verifies every signed page. Neither package is Developer ID signed
or notarized. Runtime testing and distribution signing still require a Mac.

The pinned raylib revision disables Retina framebuffers unless high DPI is
requested, but still scales its macOS viewport, clipping and render-size queries
by the monitor DPI. `build.zig` compiles a generated copy of `rcore.c` that applies
that scaling only when the high-DPI flag is enabled. The shared dependency cache
is left intact. Cistern keeps window, input and effect textures in the same
unscaled coordinate space, including after fullscreen changes.

Raw executables are under `zig-out/releases/build/<platform>-<arch>/bin/cistern`.
Transfer the archives rather than just the executables to retain maps and
launchers with executable permissions.

## Dependencies and repeatability

`tools/release-deps.json` pins the Linux development packages by version, URL
and SHA-256. The helper verifies downloads before extracting them; it does not
run package installation scripts or install anything into Windows. The Zig
dependencies remain pinned by `build.zig.zon` and their own package manifests.
The root manifest supplies archive URLs for the existing raylib revisions and
a mirror of the vanished `hexops/xcode-frameworks` repository. All package hashes
are unchanged; the direct raylib entry also avoids Zig 0.14.1's incomplete Git
fetch of its `?ref=master#...` dependency into an empty cache. macOS SDK files
stay in Zig's global package cache and are never included in the game archives.

The default dependency cache is `../.zigtoolchain/cistern-release/`, outside
this repository. First use needs network access; subsequent builds reuse it.
The Debian archive mirror is a fallback for packages moved off the live mirror.

```powershell
./build-linux.cmd --cache-dir C:/build-cache/cistern --output-dir C:/releases/cistern
```

`--zig` selects a compiler when invoking the Python helper directly; its version
must match the lock. `--build-cache` selects a separate Zig local cache, useful
for checking an independent rebuild. `--global-cache` selects a separate Zig
package/compiler cache for a completely fresh dependency check. Scratch verification outputs belong in
the system temporary directory, not in the repository.

Every invocation type-checks the executable and tests, builds ReleaseFast with
debug information stripped, inspects the executable format and dependencies,
and reopens the completed archive to verify its contents and permissions.
The helper rejects source changes during compilation. It records source,
dependency and packaged-file hashes in `build-info.json`. Archive ordering,
ownership, timestamps and modes are fixed, so unchanged inputs produce the
same archive. Asset names are sorted before embedding to avoid directory-order
differences. This is a build and packaging check; it does not execute target
tests or exercise Linux/macOS graphics drivers.

Run `python -B tools/test_release.py` to check recursive map packaging and
source hashing without cross-compiling or writing map/save files.
